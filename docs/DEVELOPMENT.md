# Development Guide

## Prerequisites
- Node ≥ 20 (developed on 22)
- npm (no runtime dependencies; dev deps only)

## Setup

```bash
npm install
npx tsc --noEmit     # typecheck
npm test             # full vitest suite
```

## Common workflows

### Run the studio end-to-end
```bash
npm run studio                 # design → build → QA → release (~30–60s)
npm run studio -- --seeds 6    # wider QA first pass
npm run studio -- --loops 4    # more fix-loop budget
npm run studio -- --skip-build # content+QA only (faster iteration)
```
Artifacts land in `studio-output/<run-id>/` — `run-report.md`, `artifacts/**`, `logs/studio.log`, `metrics.txt`.

### Play locally
```bash
npm run build:game && npm run dev   # http://localhost:6336
```

### Headless QA only
```bash
npm run qa                # suite vs shipped content/pack.json (CI gate)
npx tsx tools/qa-smoke.ts # same thing the CI runs
```

### Watch tests while working
```bash
npm run test:watch
```

## Conventions

- **Strict TypeScript.** `tsc --noEmit` must stay clean; no `any` unless quarantined with a comment.
- **ESM with `.js` import specifiers** inside TS sources (`import … from "./x.js"`).
- **Determinism rules** (engine code):
  - never read wall clock / Math.random() in `src/engine/**`;
  - draw randomness from the injected streams (`sim.rngCombat|Loot|Ai|Misc`);
  - new state must be JSON-serializable and included in `save.ts`;
  - any non-finite number must be encoded via save sentinels, not raw.
- **Sim/client separation**: the client may read sim state freely but mutates only through `FrameInput` + discrete action methods. Bots follow the same law.
- **Content changes go through the pipeline**: edit generators/banks, re-run `npm run studio`; don't hand-edit `content/pack.json`.

## Adding a feature (the honest path)

1. Engine capability → add system + unit/integration tests.
2. Content expressing it → extend banks/generators + schema validator.
3. QA coverage → new invariant or coverage flag in `src/qa/issues.ts` + harness event wiring.
4. Studio awareness → triage routing and/or a fix strategy in `programmer.ts`.
5. Docs: GDD is regenerated by the pipeline; update ARCHITECTURE/DECISIONS as needed.

## Debugging tips

- Reproduce any QA failure exactly: seed + bot seed are printed in issues; use `tests/regression/*` files as templates.
- `stateHash(sim)` compares two runs cheaply; divergence bisection pattern lives in git history (`tools/debug-save-divergence.ts` was deleted after its bug was fixed — resurrect from git if needed).
- Studio logs are JSONL: `jq -c 'select(.level=="error")' studio-output/<id>/logs/studio.log`.
- For renderer work without a browser: you're on your own — it's the one intentionally un-headless layer.

## Release checklist

The pipeline enforces this automatically, but for manual releases:
1. `npm run studio` green (QA PASS + Perf PASS + Director approved)
2. `dist/build-info.json` checksums verified
3. `content/pack.json` version matches `docs/releases/RELEASE-*.md`
4. All tests + CI pass
